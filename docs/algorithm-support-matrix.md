时间由整数 tick 和整数微秒周期决定，输入在执行扫描的时刻采样。t=0 为显式初始快照，组合块此刻不是一次已执行扫描。首个执行扫描为一个周期。输入事件恰落在采样边界时当拍生效。此调度契约为软件定义；不代表所有 Ovation 时序已核实。

已支持算法的引脚类型由规则固定，不提供用户类型覆盖。例如 ONDELAY 的 IN1 / ENBL 均为数字量（§4.68，p257），FLIPFLOP 的 SET / RSET 为数字量，ABSVALUE / 受限 GAINBIAS 的 IN1 为模拟量。可从已知引脚创建对应类型的测试源；数字测试源仅提供 TRUE/FALSE 常量、阶跃和分段保持，不提供斜坡/线性插值。已连接信号源的类型选择受连接引脚约束。明确类型的宏接口同样固定；未知接口显示待明确并阻止采用连接，不默认为数字量。类型已明确不代表时序已验证，三种计时块可执行范围分别见独立模型说明，固定参数/显式用户初态不等同控制器重启或在线整定。

导入可沿已确认的边传播已知引脚类型，推导工具接口及宏定义接口的类型并保留约束来源；数字/模拟冲突不填值，未知端口和候选连线不作为依据。此推导不提供输入随时间的工况，也不推断未知算法的运算含义。

离散结果测试采用精确相等；模拟量在支持范围内按显式 Float32 运算，不接受非有限值/次正规值。对照容差尚待参考轨迹量级和精度评审，不能将建议的 1e-6 自动视为已通过标准。记录具体正常数值向量与范围后才能扩大可靠性声明。

0.5.0只增加布局/运行分离与配置指纹、逻辑结果范围和失败诊断，未改变已有算法、Float32或扫描/计时模型。合同见reference/run-record-format.md。

0.6.1修正宏展开信息丢失：实例params/initial非空或质量非GOOD、定义输入接口含kind/wave以外参数时，在展开前拒绝并保留原工程。公开参数仍通过已映射实例覆盖配置；不将未处理字段当作默认值。核心仍0.5.0，无新增算法规则。

0.6.2只补齐辅助XML结构审计/未采用来源诊断与明确任务声明。编译XML的位置参数、类型代码及实际编译顺序未支持；不得由指令名或空值推断已支持模式。原始编译内容、未解释元素及来源任务保留，核心仍0.5.0。

0.7.1核心统一拒绝所有已支持块未声明的初态字段与损坏initial结构；只接受输出引脚初值及已声明的previousIN1。内部memory/timing等观察状态不猜作初始化别名。未知字段保留并阻止执行；合法工况的算法、扫描和计时模型不变。

0.7.2核心严格检查输入发生器各模式字段，未知单位/重复/其他键不能静默忽略。合法波形的计算及现有Ovation块模型不变；新建输入、无效配置重设及端点规则见reference/input-scenarios.md。

0.8.0核心增加已识别精度候选的逐扫描核对：GAINBIAS最终限幅输出、监视器布尔决策、计时ACT及小目标进入分支不同则停止且整拍回滚。当前支持范围附加“通过此核对”的条件，不能仅以正常有限数声称可执行；部分旧边界工况会明确拒绝。计时/监视模型v2，增益首次单独声明ref1100-2006-gainbias-v1，numericValidationModel=f32-f64-output-agreement-v1。相同候选不是所有硬件等价证明；详见reference/precision-validation.md。
