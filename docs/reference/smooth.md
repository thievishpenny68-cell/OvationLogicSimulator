# SMOOTH：指数平滑

0.35.0新增；0.36.0/引擎0.26.0采用`ref1100-2006-smooth-v2`，补齐共享消减误差检查。依据本地REF_1100（2006-05）§4.104 p363及p364页首续式。**拆分后的4.104_SMOOTH.pdf只有p363；公式位于4.105_SPTOSA.pdf第一页上部，仍属于SMOOTH。** 已对原页图核对，未根据其他PLC的滤波习惯补公式。

## 接口与计算

IN1、OUT均为LA模拟量，采用手册竖向矩形、顶部IN1及底部OUT，两端为圆形。SMTH为固定秒制时间常数，LC字段R1，新建预设0。当前不增加手册图表未明确提供的SMTH接线端。

每次扫描使用项目周期Δt（整数微秒换算成秒）和前一拍OUT：

```
beta  = exp(-Δt / SMTH)
alpha = 1 - beta
OUT   = alpha × IN1 + beta × oldOUT
```

SMTH=0时直接输出IN1，不使用oldOUT；SMTH<0会进入手册的BAD质量路径，当前全GOOD范围明确拒绝。SMTH>0时每拍递推，不额外跳过第一拍。t=0只显示用户明确的OUT初态；首执行拍将该值作为oldOUT。新建预设OUT0，导入缺失须人工补齐，不推断控制器冷/热重启状态。软件复位重新开始同样的初态实验。

当前支持全GOOD、正常有限Float32及零。负输入与负初态可以使用；BAD/无效数质量传播不以假值代替。参数、引脚或质量不支持时阻止运行，失败扫描不提交上游或下游的部分结果。

## 数值与复现

Δt、除法结果、指数结果、alpha、两个乘积和最终求和依次转Float32；另以相同Float32输入、SMTH及旧OUT，按原整数周期换算的秒数保留宽中间精度计算。v2还以`-expm1(-Δt/SMTH)`计算输入权重，避免两种候选都在`1-exp(...)`时丢失非零系数。三个最终Float32 OUT只要存在分歧、溢出或次正规中间项，就停止本拍。新增候选只用于拒绝不确定工况，不替代原输出或放行既有拒绝项；未确定Ovation内部舍入阶段，不能把任意一个候选当作现场实测值。

例如Δt=1微秒、SMTH=2^40、IN1=2^60、oldOUT=0，原两候选都得到0，未能暴露共享消减。独立100位Decimal公式计算的最终Float32为1.0485759973526；v2会报告“消减误差核对”并整拍拒绝。正负输入及非零旧值的4项独立向量见开发审查记录。这证明旧双候选一致并不保证数学精度，也没有证明实际Ovation采用哪一种舍入。

例如周期0.1秒、SMTH1、IN1=8、旧OUT0即可触发精度分歧，界面会显示原因并保留t=0。此限制也可能在长轨迹或正负抵消时出现；本模块没有用近似相等或放宽容差越过它。用户输入的外部参考容差用于对照，不能解除运行时精度检查。

运行记录同时包含状态模型和算术模型声明。本轮补齐复算检查：只要记录为当前使用的算法额外声明了另一个适用模型，两处必须与支持模型一致；不忽略相互冲突的声明。旧记录只有主要声明时仍可按原合同核对，完整逐拍快照继续精确比较。

v1完整SMOOTH记录不能按v2冒充复算一致，必须重新运行；普通工程文件仍可直接打开并按v2运行。其他算法的模型声明保持不变。

## 示例

打开`examples/smooth.json`单步8次。项目周期1秒，演示零常数直通、不同显式初态、滤波后串联及普通时间常数的稳态输入；两台示波器观察全部结果。`smooth-reference.json`包含独立字面40项执行OUT与5项初态，共45项，可用绝对/相对/时间容差0核对。

其中SMTH=Float32(1/ln2)=1.4426950216293335；本模型分阶段alpha/beta均为0.5，宽精度候选最终Float32一致，形成便于人工复核的半权重序列。这个时间安排和参考是软件工况，不是手册中的运行采集。正负阶跃、周期缩放、反向读取上一拍、无效参数、精度失败、保存重跑与全部记录复算另有测试覆盖。

另有开发审查记录保存Python Decimal以100位精度独立计算的10项公式参考，覆盖SMTH1/2/5/1000及多种周期、旧值和负输入。7项可执行结果与参考最终binary32精确一致；2项触发阶段精度分歧，1项因次正规系数拒绝。数学参考与软件运行决策分开标识，不把被拒绝工况的参考值当作可提交输出。
