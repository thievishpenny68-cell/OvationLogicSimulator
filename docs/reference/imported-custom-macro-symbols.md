# 导入时生成自定义宏外框

0.55.0 仅对源 SVG 标记为 `cb-classname="ControlMacroReference"` 的对象生成自定义宏外框。它是用户定义的图形接口，不是新增的 Ovation 仿真算法。即使宏名与 AND、GAINBIAS 等内置算法相同，也不会套用这些算法的模型或引脚许可。

## 还原内容

- 从所属子标签的 ControlPin 读取全部可见引脚，未接线的引脚同样生成。
- 原连接树确定已接线引脚的输入/输出角色；未接线引脚根据箭头及有序引脚线确定方向。
- 保留左、右、上、下的侧别和各侧原有顺序。0.55.1起按各侧针脚数量、标签宽度生成紧凑外框，针脚均匀排列，连线自动跟随新端点；原始几何仍保存用于来源对照。
- 名称可解析时显示原名称；编码仍未解明时显示 `PIN 源ID`，连接使用唯一源针脚身份，不要求用户猜测端口。
- 缺少针脚几何或角色相互矛盾时报告问题，保留原始来源，不静默忽略。

生成的数据保存在节点 `sourceMacroSymbol`、`macroPorts` 及连接来源中。每个实例独立生成，不修改全局算法目录，也不需要额外的宏定义文件。源 SVG 全文随工程保留，移动和保存重开保持引脚及连接身份。旧版已保存工程无需重导SVG即可获得紧凑显示。

## 接线和观察

导入连接按针脚身份自动接入，也可继续手工连接到宏引脚。有明确的相邻端口类型约束时，宏针脚显示数字量方形、模拟量圆形或 LP 六边形；类型不明确时保持菱形。不同宏输入、输出之间不会传播信号类型或数值，类型冲突不会任选一种。

选中宏，在右侧可查看全部针脚、所在方向和已知类型，修改模块名称、查看原 SVG 或删除图形。含这种外框的工程会明确提示它不提供仿真输出；不会把宏跳过后伪造下游结果。其他普通算法仍按原支持范围处理。已有明确宏定义的旧手工展开工作流继续保留，本功能不要求建立新的宏模型。
