# DBEQUALS精确差值核对

0.38.0/引擎0.28.0，为DBEQUALS补充基于实际Float32输入、参数和原OUT的精确布尔参考。保留原分阶段Float32/binary64核对与原输出；**精确参考只用于发现分歧并停止，不作为Ovation运算结果。** 输入、初态、参数与正常GOOD支持范围均不变。

REF_1100 §4.25 p81规定：d=abs(IN1−IN2)，d>DBND时置TRUE，d<abs(DBND−RTRN)时复位FALSE，其余保持。相等边界仍用严格比较，不添加epsilon。

例如IN1=2^100、IN2=1、DBND=2^100、RTRN=0、原OUT=TRUE。原两条有限精度路径都丢失减数1，得到d=DBND并保持TRUE；精确公式却满足d<DBND，应为FALSE。IN2=−1、原OUT=FALSE时则会漏掉置位。正负输入对称情形也有该问题。

新检查沿用内置BigInt，将相同Float32值解为2^−149的整数倍，精确比较完整差值及返回阈值。只比较最终布尔决定：如果中间值有差别、最终仍同为TRUE或FALSE，则允许通过。已有溢出、次正规或其他不支持情况的拒绝保留；不会因精确工具可计算而放行。发现分歧时诊断包含“精确差值核对”，整拍及memory不提交，失败记录可复算。

DBEQUALS模型升为`ref1100-2006-dbequals-v2`。包含旧v1声明的完整运行记录须按当前模型重跑，普通项目可继续打开、使用原参数运行。其他算法模型不变，SUM/QAVERAGE/POLYNOMIAL沿用0.37的精确参考。

开发审查记录保存13项独立Python Fraction参考，覆盖正负置位/复位、严格相等、普通回差与相消但最终布尔相同的情形。内核测试核对整拍回滚、失败复算和旧记录；离线界面测试核对实际停止与修正后运行。它们验证数学规则和软件支持边界，不替代实际控制器的中间精度、扫描或质量证据。
