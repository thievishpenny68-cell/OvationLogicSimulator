# CSV参考轨迹导入

0.42.0在“轨迹对照”中支持JSON或CSV。CSV可作为人工整理的手册期望或运行采集参考；来源类别与依据仍由本次对照明确填写。算法、扫描、数值和容差规则保持，内核仍0.28.0。

## 宽表：兼容软件现有CSV导出

前两列固定为tick、time_s，其后为当前组态中的nodeId.field：

```csv
tick,time_s,a.b.OUT,bit.OUT,p.POUT
0,0,1,FALSE,0xFFFF
1,0.1,1,0,65535
2,0.2,2,TRUE,65535
```

列名与当前信号目录精确匹配，不按点号拆分节点ID。若两个不同信号产生相同列名，不能猜是哪一个，请使用下面明确的长表。未知列或重复列也拒绝。可直接将本软件“导出CSV”得到的文件作为数值参考重新载入。

## 长表：明确节点、字段、类型

表头顺序固定，每一行是一拍的一个信号：

```csv
tick,time_s,node_id,section,field,kind,value
0,0,a.b,values,OUT,analog,1
0,0,ff,states,memory,boolean,FALSE
0,0,p,values,POUT,packed16,0xFFFF
1,0.1,a.b,values,OUT,analog,1
1,0.1,ff,states,memory,boolean,0
1,0.1,p,values,POUT,packed16,65535
```

node_id是组态节点ID；section为values（输出）或states（内部状态），field为完整字段名。kind为analog（模拟量）、boolean（数字量）、packed16（LP整字），必须与当前通道一致。可从导出JSON的信号或运行字段查看ID与字段，不凭显示名称猜测。

## 数值、时间和错误

- time_s单位为秒，tick为非负安全整数；新扫描的tick与秒时间都必须严格递增。同一拍的长表行必须具有相同time_s，同一通道只能出现一次。
- 模拟量接受有限十进制/科学计数，保留输入精度，不先转Float32；例如相邻Float32读数仍可区分。数字量仅接受TRUE/FALSE（大小写不限）或0/1，且只在明确的数字通道转换。LP接受0～65535的十进制整数或0x十六进制整字。
- 使用逗号分隔，含逗号、引号或换行的字段须用双引号包住，内部引号写成两个双引号。支持CRLF/LF/CR及UTF-8、带BOM的UTF-16，沿用现有文本解码规则。
- 不补零、不排序、不插值、不改扫描编号。非法类型/数值、空值、空白记录、错列、未闭合引号等显示CSV行号并拒绝。长表未提供的通道或扫描，由原对照报告明确标为缺失，不自动生成期望。

文件加载失败会清除旧参考和旧报告，避免误用上次文件；可修正后重新选择。0.44起，连续选择文件只采用最后一次选择的结果；旧读取的成功/失败不覆盖当前结果，不清空更新的选择。最新文件失败时也不会回退到较早文件。CSV仅作为参考对照，不是包含组态、全部状态和模型的完整复算记录。

## 练习

1. 打开`examples/csv-comparison.json`，单步两次。
2. 展开底部“逐扫描 / 对照信号（含内部状态）”，保留四路输出并勾选ff的memory，共五路。
3. 在“轨迹对照”载入`examples/csv-comparison-reference.csv`，来源选择“手册”，说明“输入与置位优先真值表手工推导，非现场采集”，三个容差均0。
4. 应得到15/15样本匹配。可以导出对照报告，或导出当前CSV再载入，验证宽表往返。

例子用输入源采样、FLIPFLOP TYPE=1置位优先及PACK16无已接输入时保留初始字的已支持规则；参考是独立字面值，不从执行轨迹生成。

CSV没有算法模型/扫描模型等声明，导入器不会从当前工程补写这些信息。因此数值相同仍显示模型信息未完全核对，不提升为Ovation运行验证。布尔/LP精确比较、模拟量绝对/相对误差和时间容差、按tick对齐、来源说明及JSON原有模型检查保持。
