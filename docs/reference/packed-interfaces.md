# 打包点接口沿革（0.26起已可执行）

> 0.26.0起，以下接口已升级为可运行LP整字算法；当前范围和共享点合同以[packed-words.md](packed-words.md)为准。下面保留原接口阶段的诊断背景。

0.11.1、核心0.8.2。PACK16/UNPACK16只提供手册明确的端口和引用识别，未加入可执行控制块库。

|算法|输入|输出|
|---|---|---|
|PACK16|可选数字D0～D15，对应第0～15位|POUT，别名PBPT；打包点域packed16|
|UNPACK16|PIN，别名PBPT；打包点域packed16|可选数字D0～D15|

打包点指LP或更大点记录的A2字段。REF1140 §4.2.5 p90将其定义为16个数字点的当前值，并另有A3有效状态等字段。因此不能将POUT当作普通模拟量输出，也不能用0代替缺失初始字值。

导入器可恢复明确的D输入引用，并沿已确认边将其测试源限定为数字量；只识别LP点记录声明不会进行这种类型推断。PBPT别名按所属算法归一到POUT/PIN，未知算法或同名宏不借用这些标准接口。

允许编辑同类型packed16端口连线，但不提供打包字发生器、数值转换或运行结果。核心生成INTERFACE_ONLY及打包点未支持诊断；即使普通导入问题全部人工确认，仍不能运行。缺失类型、参数和原始字段继续保留。

完整实现还需要明确A2初值、未接位保留、BAD输入位保留、共享PBPT写入和质量/强制状态。手册允许多个算法写不同位，不能把每个块独立从零打包当作等价实现。本轮不模拟这些行为。

依据：本地REF1100(2006)§4.71 p261～262、§4.124 p420～421，REF1140(2005)§4.2.5 p90；[2016原厂手册§5.77 p362～363](https://www.scribd.com/document/1074913829/OW360-R1100)对位序、可选输入、PBPT共享和BAD位保持给出相同主要规则。接口识别不代表算法准确性验收或完整记录类型支持。
