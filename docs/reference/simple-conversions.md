# 基础转换与蒸汽流量补偿

产品1.2.0新增四种手册算法，内核0.31.0。全部沿用正常有限Float32、GOOD质量及逐扫描原子提交合同。手册公式、独立高精度参考和软件回归是本次依据，尚无Ovation逐扫描运行对照。

## STEAMFLOW

依据REF_1100 §4.109，p386–387。IN1、IN2、OUT均使用LA。

- TYPE默认DELTAP：`OUT = SCAL × sqrt(IN1 × BASE / (IN2 × GAIN))`。
- TYPE=FLOW：`OUT = SCAL × IN1 × sqrt(BASE / (IN2 × GAIN))`。
- SCAL、BASE、GAIN默认均为1.0。BASE是基本比容，GAIN是比容增益，SCAL是输出标度。
- 用户必须提供单位一致的差压/流量和比容；比容可用INPUT输入，不要求另外实现STEAMTABLE。
- 分母为0、负根号、非有限/次正规中间结果，以及Float32逐步运算和宽精度候选不一致时停止本拍。不会擅自改变公式顺序来掩盖精度问题。
- 导入只接受明确的DELTAP/FLOW模式名称；手册未给出可靠映射的数字TYPE编码不猜解。

## SPTOSA

依据§4.105，p364。PACK为LP整字，OUT为LA。第15位未置位时输出非负整数；置位时按补码输出负整数。支持0～0x7FFF、0x8001～0xFFFF。

原文同时写了−32767～32767的范围；0x8000对应的极值不在本轮支持范围，遇到时明确停止，未直接采用通用编程语言的−32768解释。页面上方属于上一算法的平滑公式不参与本块。

## SATOSP

依据§4.92，p331。IN为LA，PACK为LP整字；无整定参数。

输入限幅到−32767～32767，再取最近整数，编码为16位补码。正半整数向上；负半整数在手册没有给出足够明确的方向，本轮拒绝区间内的这类输入。例如−1.5停止，而−1.49编码−1、−1.51编码−2。超出手册上下限的输入直接取相应限值。LP零统一为正整数0。

支持显式LP共享字整字写入，并与PACK16等位写者按确认的扫描顺序一起工作。后续读取可以通过连线接到SPTOSA；共享身份和初值必须明确。BAD/无效输入保持上次值的质量分支未实现，仍由GOOD质量前提阻止。

## ANTILOG

依据§4.9，p39–40。IN1、OUT为LA；FOUT允许LD或LP位形式，当前标量执行为数字量。BASE默认0（e底）；正整数字节1～255均选择10底。SCAL默认0.0，因此默认正常输出为1，不能当作缺少参数或自动改为1。

先计算已标度指数IN1×SCAL。本轮保守的基础支持范围为：

- e底：−80～80。
- 10底：−34～34。

这两个范围是本软件主动限制，不是声称Ovation实际溢出阈值。范围内FOUT为FALSE；超出范围不猜测饱和值或标志阈值，停止本拍且不提交其他块的新状态。逐步Float32和宽精度候选最终不一致时也停止。

## 示例与核对

打开examples/simple-conversions.json，100ms单步5次：流量补偿在0.1秒为6，0.3秒切换为4；SATOSP/SPTOSA转换后数值相同；指数输出在0.1秒为10，0.4秒切换为100。将STEAMFLOW改成FLOW后，初始输入对应18。t=0保留明确的软件起点，不冒充一次已经执行的扫描。

examples/simple-conversions-reference.json为48个手算观察值。另有352个100位Decimal独立参考向量，以及65535个已支持打包字的转换与回转检查。参考资料证明覆盖用例的结果，不代替实机行为证据。
