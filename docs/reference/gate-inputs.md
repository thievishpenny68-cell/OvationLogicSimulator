# AND / OR 输入引脚选择

0.12.0、核心0.9.0。属性区可逐个勾选参与运算的数字输入。IN1、IN2在当前支持范围内必选，IN3～IN8可独立选用。例如选择IN1、IN2、IN8时，画布和计算保留这些编号；IN3～IN7不参与运算，不被补成FALSE或TRUE。

选中的每个引脚都必须接线。取消选用一个已接线引脚时，原连线保留，系统报告未知端口并阻止运行，直至重新选用或人工删除该线。选择改变属于逻辑修改，会清除旧运行记录，来源扫描计划须按现有规则重新确认。已接引脚始终为数字量，测试信号只提供布尔调整。

明确的SVG/MCR `cb-alg-inN`引用按原编号恢复，不以最大编号制造中间输入。空/损坏引用继续报告问题，缺少IN1或IN2不会自动补信号。仅有布局位置的连接保持候选；明确声明与连续编号布局假设冲突时，不提供错误的连续编号建议。

旧工程`params.inputs: 2..8`仍表示连续IN1至INn。新增数组形式表示准确的端口集合，例如`["IN1","IN2","IN8"]`，要求名称有效、无重复且包含IN1/IN2；数组顺序不影响布尔结果。属性区保存连续选择时使用旧数字形式。坏配置保留原JSON并阻止执行，需明确修改；普通应用参数不会将其替换成缺省两路。旧版引擎不认识数组形式，会拒绝执行，应使用0.12.0及以后版本。

依据REF1100(2006)§4.7 p36的AND定义：IN1/IN2必选，IN3～IN8可选；§4.70 p260的OR定义：IN3～IN8可选。OR的描述写2～8路，而表格将IN2列为可选，当前继续限制至少IN1/IN2，不据此开放单输入OR。布尔公式和扫描顺序规则未改。

`examples/gate-inputs.json`给出IN1/IN2/IN8分别在0.2/0.4/0.6秒置位的工况。两门初始输入均FALSE：OR在0.2秒首次TRUE，AND在0.6秒首次TRUE。软件测试覆盖全部64种可选集合以及各自完整真值表，共5832次输出判定，并覆盖记录复算；这些是手册规则的软件验证，没有新增Ovation运行采集。

0.23.0起，AND/OR图例仅绘制已选输入。2路就是2个箭头/端点，3路就是3个；门体及输入排布随数量调整，保留手册D形AND和圆形OR。选择IN1/IN2/IN8时不重命名成IN3，也不显示未选IN3～IN7。
