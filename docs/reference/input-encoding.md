# 文件编码与读取失败

0.14.0起，Control Sheet多文件导入、打开工程、参考轨迹及复算记录共用严格文本读取。合法字符保持原文；非法字节不替换成“�”继续解释。文件中原本合法编码的“�”字符可以保留。

|文件编码|读取范围|
|---|---|
|UTF-8|有或无UTF-8 BOM均可|
|UTF-16LE / UTF-16BE|有对应BOM的XML、TFT、JSON、CSV均可|
|无BOM的UTF-16 XML|须以XML声明开始，字节前导和明确UTF-16LE/UTF-16BE声明一致|
|XML通用UTF-16声明|须有UTF-16 BOM，不能凭平台习惯选字节序|

XML编码声明须与实际读取方式一致。未支持的声明、UTF-32、非法/不完整字节、孤立UTF-16代理以及原文NUL空字符均停止读取，报出文件名和原因。没有标记的本地代码页不作猜测；请在源软件中转存为UTF-8，或带BOM的UTF-16后重新导入。JSON中的正常转义文本不属于原文NUL。

任一选中文件解码失败时，多文件导入整批不提交，当前工程、来源和运行历史保持。打开损坏工程也不替换当前项目。0.42起参考文件失败清除之前参考及对照，当前工程/运行不变；0.44起只处理最后一次参考选择的读取结果，过期读取的结果/错误不覆盖新参考；复算仍在临时状态核对，未经成功核对和明确载入不替换当前运行。

0.14.1起，所有选中文件中找不到可识别的ControlFunction/ControlMacro目标时（例如普通SVG、仅MCR/TFT、不完整XML），显示文件名及格式原因，保留当前工程、运行记录和撤销状态；可重选文件。识别到目标后，空图、未知控制块、缺参及辅助文件错误仍按原规则导入，保留原文并进入问题清单供人工补充。找到目标不表示内容或算法已通过验收；不按节点数或问题数决定是否替换图纸。

保存工程和导出记录继续使用UTF-8 JSON；源文件不会被改写。来源审计保存的是原文字内容，BOM属于编码标记，不作为文档字符。严格读取不证明内容真实性或算法准确性，也不增加算法执行范围。

依据：[W3C XML 1.0 §4.3.3](https://www.w3.org/TR/xml/#charencoding)的编码声明/BOM要求及[附录F](https://www.w3.org/TR/xml/#sec-guessing)的字节前导识别；[WHATWG Encoding TextDecoder](https://encoding.spec.whatwg.org/#interface-textdecoder)的fatal错误模式。当前工具仅实现上表范围，不宣称支持所有XML字符编码。

验证包含UTF-8/UTF-16两种字节序、声明冲突/无BOM/截断字节、中文/非BMP字符及原本合法的U+FFFD；11份标准来源的新旧解码文字一致。解码严格性的软件测试不是Ovation运行采集。
