# 单任务逐块扫描模型 v1

0.63.0起可按[模块禁用规则](disabled-blocks.md)缩小参与范围：人工禁用、连线下游依赖及LP共享字组不执行。显式顺序按参与块取子序列，独立部分保持原逐块读取规则；恢复不构造缺失初值或猜测算法输出。画布上方持续显示禁用、依赖暂停和参与块数量。

引擎0.4.0，manifest.scanModel=`single-task-ordered-v1`。算法profile及计时模型保持原版本。依据已批准的确定性扫描设计，以及execution-and-timer-rules.md中的R1资料核查；此处定义可复现的软件模型，不声称恢复未知版本FastBoolean编译顺序。

## 顺序与取值

每拍按公开顺序执行所有节点各一次。读取的源节点已在本拍执行时使用本拍输出，尚未执行时使用上一已提交扫描输出。INPUT也是软件节点：执行时按本拍整数逻辑时刻采样，排在它前面的块回读其上拍采样。t=0的INPUT来自已定义工况，其他节点来自已声明初态或既有模型的初始快照。

顺序反向读取的非INPUT输出必须具有明确、类型正确的初值，不能靠默认FALSE/0补缺；普通组合块属性可填写“仿真起点OUT（顺序回读时使用）”。计时器OUT/ACT和沿检测初态继续遵守各自模型。无环拓扑的正常前向边不额外增加一拍。每拍仍在副本计算，任一块失败不提交时间、输出或状态。

自动拓扑按依赖生成，独立节点以字符串ID确定性排序，只是软件建议。ID、图元容器顺序及坐标都不作为Ovation实际执行序号的解码依据。人工模式须包含全部节点各一次；残缺、重复、未知节点、未知模型或模式报错，不切换到另一顺序。存在有向环时仍报FEEDBACK_UNVERIFIED，人工提供顺序也不解除；尚未核实的反馈点/布尔表达式编译边界不能按这个模型猜测等价。

## 确认及失效

导入图及导入宏展开后的调用图必须在“扫描设置”明确确认周期、顺序和依据。旧导入项目即使缺execution字段、普通导入问题已确认，也需要补充扫描计划。新建手工无环图可直接使用公开的默认拓扑顺序，手工改变顺序后必须明确采用。

确认签名涵盖周期、模式、顺序、节点身份/类型/声明引脚、连接及来源任务约束。改变这些内容使确认过期；位置、名称、波形、普通参数、初态及观察布局不改变顺序签名，仍按现有规则重新校验并清除旧运行记录。改变模拟周期后不能沿用旧确认。未采用的顺序草稿不参与运行，补初态后保留草稿依据。运行期间锁定计划编辑。

确认只处理扫描周期提示，不清除其他来源、参数、输入、类型、质量或未知块问题。签名用于判断配置是否变化，不是密码学证据或来源真实性证明。完整运行配置和实际顺序随manifest导出。

## 来源任务边界

新导入保存选定SVG及同名MCR内所有明确cb-task-id声明，保留文件/对象/类/原始字符串。任务编号不推断周期；空值或没有声明表示任务信息未明确，需人工确认仅按软件单任务模拟。同一来源组有多个不同非空标识时，按多任务或来源冲突阻断，普通问题确认和扫描计划采用均不能绕过。

宏展开保留各定义的独立任务约束组及作用域，不把不同模板的本地任务编号强行比较为同一物理控制器任务；定义内部多个标识的阻断仍保留。没有元数据的旧导入需要人工核对单任务前提，不能据此宣称已自动解码其任务边界。本模型未实现多任务/跨任务调度。

## 工程格式

新工程和保存工程使用schemaVersion=2，避免旧0.3系列忽略execution后按另一顺序运行。当前界面兼容读取版本1并升级保存；内核仍支持版本1无扫描计划的旧手工图，含扫描计划或任务约束的版本1对象明确拒绝。算法profile不变，导出manifest记录引擎0.4.0、模型、实际顺序、确认依据及完整工程。

包内examples/explicit-scan-order.json为三节点软件示例：INPUT→NOT A→NOT B，显式顺序B、A、INPUT，已知初值均FALSE。第一拍A/B为TRUE，第二拍A/B为FALSE，第三拍B恢复TRUE。该瞬态用于解释顺序/初态，不是Ovation实机读数。
