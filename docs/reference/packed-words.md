# PACK16、UNPACK16 与共享 LP 字（0.26.0）

核心0.17.0，当前45种可执行手册算法。依据REF_1100（2006-05）§4.71 p261～262与§4.124 p420～421，原有接口升级为可运行的GOOD质量模式。

## 位与类型

- PACK16的D0～D15均为可选LD数字输入，输出POUT（PBPT别名）为LP.A2字。只把已接输入写到对应位：TRUE置位，FALSE清位。未接位保留原字中的值，不补FALSE。
- UNPACK16输入PIN（PBPT别名）为LP字，D0～D15为对应LD数字输出。第0位权重1，第15位权重32768。全部输出可观察，未接到其他块的输出不影响执行。
- packed16是独立类型，只允许0～65535的整数。模拟量、布尔值、负数、分数和越界数不能冒充LP字；也不能把LP整字接到数字位输入。ASSIGN支持LP到LP同类复制，INPUT/单输入OUTPUT支持LP测试/观察。
- 测试源可配置常量、阶跃和分段保持；允许十进制或`0x`十六进制输入，不提供斜坡和线性插值。记录仍存精确整数；连线、节点和示波器以十六进制显示，连线悬停同时给出十进制和16位二进制。示波器与趋势按离散阶梯绘制，参考对照对LP字逐整数精确比较，模拟容差不能掩盖位差异。

## 共享点与逐扫描顺序

独立PACK16使用其显式POUT初值，未写位在运行中保持。源图中有明确LP点名时，必须完成共享字身份和初值配置，不把每个节点默认当作独立点。

在PACK16、UNPACK16或LP模式ASSIGN属性里填写“共享字名称”和初值，点击“应用LP绑定”。已有名称可复用；同名写者和该字的软件起点一起更新，修改会清除旧轨迹，可撤销。UNPACK16可直接读命名共享字，或者通过PIN接线，不能同时设置两个驱动。

共享字必须在“扫描设置”选择明确顺序并确认。每个PACK16执行时读取当前字、仅修改自己已接位、写回同一个字。相同字的各输出别名显示当前记录值；UNPACK16输出保持它执行时读到的位。若两个写者写同一位，以确认顺序中的后写者为准；未连接的位始终保留。其他块运行失败时，本次扫描全部输出和共享字一起回滚，不泄露半拍修改。

项目可选字段`packedPoints:[{"id":"WORD","initial":16384}]`声明软件初态，节点`packedPoint:"WORD"`绑定。写者初态必须与共享字一致；缺失、重复身份、初态冲突、源同名绑定不同字或实际驱动不符均明确拒绝。绑定及初态参与扫描确认签名和工程指纹；改动后旧确认过期。宏展开为每个实例隔离内部共享字，防止不同宏中同名本地点串扰。

共享字运行快照额外含`packedPoints`和`packedReads`（各块实际读入字，区别于扫描末尾值），完整导出与复算逐字段核对。对旧的无共享字项目，不添加空状态，不改变既有扫描签名；旧记录仍按原有兼容性规则核对。

## 示例与验证

打开`examples/packed-words.json`，单步4次。packA写D0/D15、early读取、packB写D1/D2、late读取。D14未接输入，从初始0x4000持续保留。最后共享字及两个POUT别名均为0x4002；early.D2仍TRUE（第二写者执行前读取），late.D2为FALSE。

`examples/packed-words-reference.json`为独立手工位掩码参考，未调用引擎生成。在信号选择中只选packA.POUT、packB.POUT、early.D1/D2、late.D1/D2/D14，按人工整理和零容差对照，应35/35匹配。全部65536字组合、稀疏位、共享读写顺序、宏隔离、失败扫描原子性、保存重跑和完整复算均有软件回归。

当前不模拟硬件总线广播、BAD/POOR输入质量及未解析的LP位地址，也不支持豪华点。出现这些来源声明仍明确拒绝。LP整字执行并不开放“整字当作布尔位”；手册LD/LP数字引脚中LP位引用需要明确位地址模型，不能自动推断。本版证据不代表Ovation现场运行采集。
