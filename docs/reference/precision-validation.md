# 精度分歧核对 v1

0.38.0/核心0.28.0：DBEQUALS v2追加精确差值布尔参考，识别共享消减造成的置位/复位分歧，见dbequals-exact-check.md。SUM v3、QAVERAGE v2、POLYNOMIAL v2保持精确公式参考。数学参考不选择实际控制器运算；下文带旧版本的条目保留沿革。

本功能自产品0.9.0、核心0.8.0提供，当前产品0.36.0/核心0.26.0。依据REF_1100（2006-05）的算法规则及OW360_R1100（2016-05）§2.5对点值/内部计算精度的区分，当前不能证明所有实际平台都采用同一种中间舍入。

因此运行时核对已识别的精度候选。**结果不一致时停止本次扫描，不选择某个候选冒充Ovation结果。** 候选一致只说明通过本项核对，不证明所有硬件精度、编译优化、扫描相位或异常质量行为都等价。

## 核对范围

输入点、参数与初始模拟输出仍按当前正常有限Float32/零合同处理。以相同输入及状态分别计算既有分步Float32结果和采用JavaScript binary64中间运算、最后转换为Float32的候选；后者不是无限精度运算，也不指定为Ovation的实际实现。

|算法|核对的位置|不一致时|
|---|---|---|
|GAINBIAS|乘加分阶段舍入与中间保留binary64；比较最终限幅后的Float32 OUT|整拍拒绝；限幅后相同则不因隐藏的中间差值误拦|
|SUM / MULTIPLY / DIVIDE / HISELECT / LOSELECT|SUM已接2～4路、其他当前两路；增益偏置及运算分阶段Float32，与保留binary64中间结果比较最终限幅OUT|最终OUT不同则整拍拒绝；除零明确采用手册限值分支|
|SMOOTH v2|分阶段Float32、原binary64公式，以及用-expm1求小输入权重的消减抵抗候选|任一最终Float32 OUT不同即整拍拒绝；不选择某候选冒充控制器结果|
|QAVERAGE / FUNCTION / INTERP / POLYNOMIAL等含多步运算块|按各块文档，对已识别的分阶段与宽中间运算比较最终输出；见对应reference文件|不同或不支持的中间数值均拒绝；非全部硬件实现证明|
|DBEQUALS v2|差值及返回阈值的Float32/binary64候选，追加整数精确差值参考，比较严格回差规则后的布尔OUT|实际布尔决策不同才拒绝；相等边界不加epsilon|
|HIGHMON / LOWMON|复位阈值差/和的Float32与binary64比较；遵守先跳闸后复位顺序，比较实际OUT|布尔OUT不同才拒绝；若先前OUT已FALSE、两个分支最后都FALSE，允许执行|
|三种计时块|秒数、除BASE、加ACT锚点逐步舍入，与中间保留binary64的ACT候选|ACT不同则拒绝，即使本拍OUT暂时相同|
|ONDELAY / OFFDELAY|进入首拍累计前的小目标判断：既有时长/Float32周期比较、时长先Float32以及两者binary64的比较|分支选择不同即拒绝，不在ACT核对之前悄悄选择计时起点|

比较使用精确值，不用epsilon或放宽容差掩盖分歧。正负零仍按JSON数值语义相等。既有不支持的溢出、次正规值和非GOOD模式继续明确报错，不因其中一个候选能计算就扩展支持。

这会收窄此前只有单一软件精度约定的可执行工况。例如BASE=1、TARG=0.1、周期0.1秒的边界，或BASE=0.3累计到目标附近，也可能因候选分歧而停止；不能将十进制简写的相等当作内部计算已确定。不要为了通过检查随意改参数；应保留诊断和配置，查适用版本依据后再评估模型。

## 可复现反例

HIGHMON：HISP=1、HIDB=3×2^-25、初始OUT=TRUE、IN1=0.9999998807907104。Float32复位阈值等于IN1，保持TRUE；binary64阈值为0.9999999105930328，按同一严格小于规则会复位FALSE。LOWMON也存在对称反例。

GAINBIAS：IN1=0.7、GAIN=1.1、BIAS=0.3、限幅±4，两个最终Float32候选分别为1.0699999332427979与1.0700000524520874。

小目标：BASE=0.7、TARG=1/7、周期0.1秒，TARG与BASE先转点值格式后，其乘积的中间精度可改变首拍累计分支。仅核对ACT公式会漏掉这个分歧。

这些是独立数值反例，不是现场采集。`examples/precision-sensitive-monitor.json`用于查看停止诊断；其他既有普通示例仍可运行。

## 状态与诊断

失败扫描不提交tick、输入采样、输出或内部状态，画面保留最后有效快照。运行自动暂停并打开问题页，显示候选、节点和失败扫描，可“定位”控制块；页脚悬停可查看完整信息。运行诊断不写进项目导入问题，也不能用普通“人工确认”绕过。

布局/观察修改保留诊断。修改逻辑配置或复位后清除，重新计算。JSON运行记录保留最后失败诊断和已提交范围；复算包含该失败尝试，载入后恢复诊断，不将失败当作有效快照。

## 模型声明与旧记录

- numericValidationModel：`f32-f64-output-agreement-v1`。
- arithmeticModels.GAINBIAS：`ref1100-2006-gainbias-v1`（首次单独命名的增益模型）。
- arithmeticModels.SUM为`ref1100-2006-sum-exact-check-v3`；MULTIPLY/DIVIDE/HISELECT/LOSELECT为`ref1100-2006-<小写算法名>-v1`；monitorModels.DBEQUALS为`ref1100-2006-dbequals-v2`。
- SMOOTH的arithmeticModels与stateModels均为`ref1100-2006-smooth-v2`。旧v1完整记录须重跑；正常工程可直接用当前模型运行。详见`smooth.md`与独立消减向量。
- monitorModels：`ref1100-2006-monitor-v2`。
- timerModels：ONDELAY为`ref1100-2006-scan-v3`（修正恢复累计）；OFFDELAY/ONESHOT为`ref1100-2006-scan-v2`。

包含这些块的完整记录复算必须有相应当前声明；缺失或旧模型明确拒绝，不给旧记录补写新版本来声称相同。无相关块的旧布尔记录仍可按其相同声明模型核对。参考轨迹比较会核对双方已提供的新声明；缺失则标明未核对，不能把数值相同当作模型一致。

新版不重放旧引擎。需要复查此前软件约定时保留旧包、原工程和原记录；这仍属于软件复现，不等于该约定已获实际平台确认。计时首拍、恢复和重触发的扫描约定仍按各自状态机文档公开；本项检查没有替代这些证据边界。
