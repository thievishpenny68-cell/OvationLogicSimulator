# 联合导入宏的集中来源核对

0.41.0修复多文件联合导入后，展开宏的MCR交叉核对误报原来源缺失的问题。内核仍0.28.0，算法、扫描和数值模型不变。

联合导入一张主图和配套宏时，原始文件集中保存在项目sources；库定义的sources为空，以避免在每份定义重复保存全文。旧核对器只在定义内部找SVG/MCR，因此即使原文件仍在项目中，也不能显示吻合连接。

## 修复后的规则

只有选中的宏定义明确具有空sources数组时，核对器才使用当前项目的集中来源；每个原SVG/MCR必须满足：

1. 原文件名在集中来源中恰好出现一次。
2. 主导入的文件用途清单中，该文件也只有一项记录。
3. 记录明确以macro-definition或macro-implementation关联到本宏原图，而不是其他宏或主图。

定义本来保留独立来源时，继续使用定义内部文件，不混用父项目来源。缺失/重复/未建立用途对应仍显示证据不足；其他端口类型、节点关联、作用域、原引用与当前唯一驱动检查照常执行。不重新读取磁盘，不复制或生成来源，不新增或重连语义边。

## 如何使用

同时导入主图、宏SVG及其MCR/TFT等配套文件。明确宏接口及实例绑定，展开后进入“检查与导入问题”的MCR核对区。只有符合全部条件的行可选择；对照原图、填写依据后采用，未选择的其他实例仍待核对。采用可撤销/重做，保存重开保留集中来源、原审计和每个实例的决定。

旧工程如果本来已保存完整的集中来源及文件用途记录，重开即可使用该修正；缺用途记录时继续逐条核对，或先保存人工改动后重新导入原资料。不能仅添加一个同名文件就获得吻合结果。

## 当前证据

软件工况从实际导入器生成去重的库，两次展开后共4条内部连接可核对；只采用第一实例的2条不会确认第二实例。来源缺失/重名、用途缺失/重复/指向其他宏均拒绝，过期批次整批不提交。离线界面覆盖报告、采用、撤销、保存重开和其他问题继续阻止运行。

真实4份SVG与配套文件联合导入，自动选中唯一ControlFunction主图14FA，提供3份宏定义。展开DSI后，旧核对器因查找位置错误而全部失败；修复后仅4条类型、端口和引用明确的内部连接可核对，19条候选仍全部待人工处理。其他缺参/类型/编译XML及扫描前提不因此确认，详见开发审查记录。

该变化修复来源存储路径，不增加SVG编码解码或现场运行证据。原始文件/审计与图结构保持，证据含义沿用`mcr-connection-review.md`。
