# BCDNIN / BCDNOUT

依据本地 REF_1100（2006-05）§4.17 p53～55、§4.18 p56～58。示例 `examples/bcd.json` 与字面参考 `bcd-reference.json` 共30项输出，包含6281直接/反向转换、28的局部写入及窗外保留。证据为手册规则和软件回归，尚无Ovation运行采集。

- BCDNIN：IN严格为LP打包字、OUT为LA模拟量。BCDNOUT：IN为LA、OUT为LP。真实输入名称是IN。端点模拟圆形、打包六边形，主体采用手册给出的顶部输入/底部输出矩形。
- NDIG为1～4，BITP为最低数字开始的比特位。当前LP.A2支持0～15位，整个窗口必须处于16位字中。软件新建BITP=0；导入缺失BITP仍需补充，不把软件预设当作来源事实。
- CNTL=0直接，CNTL=1对选定窗口按位取反。每个十进制数字占4位，低位数字位于低比特位置。示例6281对应0x6281/0x9D7E。
- BCDNOUT只改窗口，其余位保留，因此需要明确OUT初值。BITP=4、NDIG=2、初值0xF00A时，28写成0xF28A；反向写成0xFD7A。
- 同一LP点的多个写者通过属性绑定共享字，统一初值并明确逐块扫描顺序。每个写者读取本扫描此前写入的当前字，不覆盖其他窗口。连线读者也读取其执行时的字。完整运行记录保存共享字与实际读取值。

支持范围：GOOD质量、16位LP字；编码仅接受0～10^NDIG−1的整数，解码每个半字节必须为0～9。手册未明确小数取整、负数、超出位数或A～F的规则，这些输入停止扫描并保留上一完整扫描，不截断、猜测或静默忽略。编码输入是LA，不能因此将端点改为数字量。

手册另述无效实数不写输出。本软件既有数值合同仅接受正常有限Float32和GOOD质量，当前会在无效源处明确停止，不宣称复现硬件的无效实数/质量传播路径。所有BCD有效整数均可被Float32精确表示；打包字逐位精确，不适用模拟量误差容限。t=0为明确的软件扫描前输出，首扫描才执行转换，不代表控制器上电初始化。
