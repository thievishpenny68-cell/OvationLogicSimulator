# 手册引脚与基础点记录类型

当前0.36.0/核心0.26.0：52种可执行手册算法、302个最大配置引脚；FUNCTION.IN1/OUT与SMOOTH.IN1/OUT均仅LA。SUM可选IN3/IN4、QAVERAGE.IN1～IN8/OUT、TRANSPORT.IN1/OUT也仅LA；BCDNIN.IN/BCDNOUT.OUT仅LP，反向两端仅LA。运行表与逐模块证据见开发审查记录。

审查沿革：0.24.0/核心0.15.0首次逐份核对40种算法及当时的PACK16/UNPACK16接口，共192脚；后续按新增算法扩充。下表描述当前执行范围。

|基础点记录|含义|当前执行范围|
|---|---|---|
|LA|模拟点|正常有限Float32，沿用数值合同|
|LD|数字点|严格布尔true/false，不接受数字0/1替代|
|LP|打包点|独立uint16整字0～65535，支持已实现块及明确共享字读改写；未知位地址不猜解|

DA/DD/DP豪华点及LL/LX等未实现声明不推成LA/LD。LC是算法存储记录，参数及ACT等运行存储按角色保留，不受信号点三类白名单误拒。未知原字段保留，普通“人工确认”不能解除重新计算的类型错误。

手册逐脚许可见开发审查记录；包含章节、纸页、PDF页和对应表行。运行时小表为`src/pin-record-data.js`。基础许可的重点差异：

- 多数数字引脚允许LD/LP，但LP许可不代表可以把整个打包字当作布尔值。
- COMPARE.ENBL/OUT/OUTG/OUTL、HIGHLOWMON.OUT、INTERP.VALID仅允许LD。
- PACK16.D0～D15、UNPACK16.D0～D15仅允许LD；PACK16.POUT/PBPT、UNPACK16.PIN/PBPT为LP整字。
- ASSIGN（§4.13 p44）允许LA/LD/LP，三种模式均可执行，但输入与输出必须为同一记录类型；LP共享点身份、初态和扫描顺序须明确。

具名来源点按明确属性、已连接的源引脚与TFT声明关联，不用图形位置或数值0/1猜类型。宏展开作用域隔离同名本地点，跨域沿实际源解析。未归属ALGID的TFT声明也纳入类型校验；原始导入审计保持快照，新的诊断重新计算。无来源声明的手工测试节点按其已确认类型使用LA、LD或LP。悬停输入/输出端子可查看手册允许的记录类型。

真实样本中的LL/LX仍保留并报告；ALR/CPL原53条MCR候选中35条可继续核对，18条因未支持点类型保留待核对。原SVG显式连接分母、全部来源原文和原始字段均未改变。

## OUTPUT单输入终端

OUTPUT只显示并接受一个IN1，没有可接线的OUT。观察读数、属性中的“读数→探针”、逐扫描记录与CSV/JSON仍可使用；历史观察通道键保持，观察读数不产生可驱动控制连接。

宏公开输入展开为ASSIGN传递节点；宏公开输出直接重连到终端IN1的真实内部驱动。驱动未唯一确定时保留原待修复连接并提示，允许展开后人工补充，不猜信号源。旧项目若从OUTPUT.OUT向后接线，会保留该线并报告端口不存在，须改接真实源；旧运行记录若依赖此结构不能按当前引擎复算。包内修复示例已更新，0.5.0历史运行记录保留为明确拒绝的兼容性证据。

0.25.0增量：AVALGEN.OUT允许LA；DVALGEN.OUT允许LD/LP；TRNSFINDX.IN1/IN2/O01～O64允许LA。完整审计扩至43算法+2接口、260脚，原LP执行边界保持。

0.26.0更新：LP整字执行已在明确0～65535域实现，PACK16/UNPACK16现为可执行算法，共45种；ASSIGN支持LP同类复制。共享字身份/初态、源同名别名及实际驱动必须一致，明确顺序和整拍原子性见packed-words.md。LP数字位引用、豪华点和BAD/POOR仍未实现；不要把“LP允许的数字脚”直接接入整个字。前述0.24/0.25限制为历史范围。
