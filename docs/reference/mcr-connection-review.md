# MCR 连线交叉核对

0.13.0提供人工批量核线入口。在“检查与导入问题”中，系统比较SVG候选列出的端口、当前已导入的边，以及同一来源导入审计中的MCR明确引用。它不会在导入时自动采用候选。

先对照原SVG检查所列连接，再勾选需要采用的吻合项；也可点击“选择全部吻合项”。填写本批的人工核对依据，点击“采用所选吻合连接”。一次撤销恢复整批；工程保存后保留每项决定及交叉证据。采用前可导出JSON核对报告，查看MCR文件、目标属性、原引用、当前端口和不可采用原因。

批量入口只确认已存在的MCR边，不新增、删除或改接逻辑边。没有勾选、缺依据、任一选择已过期或不再吻合时，整批不提交。其他未知块、缺参、初态、输入工况、扫描顺序、反馈及质量问题继续保留并阻止运行。普通逐条核对、补线、源图预览仍可使用。

0.41.0修复联合导入库定义的集中来源查找：定义sources为空时，按当前项目的原文件与宏用途清单核对，不再误报缺失。唯一性/宏归属仍必须满足，详见`shared-macro-sources.md`。

## 可列为吻合的条件

- 原连接实例只有一个待处理候选；端点及所列端口完整且类型相同。
- SVG与MCR对象各自唯一对应。仅按“唯一算法类型”摆放的位置不能作为语义依据；来源冲突、重复对象或缺失来源排除。
- 当前目标只有一个驱动，且恰好是所列源端口。
- 当前边的MCR属性和值，与原审计对象上的`$对象ID$cb-alg-输出字段$`引用一致；按已知算法接口核对输入/输出端口。
- 宏展开按原定义审计及当前实例作用域独立核对。公开INPUT转换为OUTPUT传递节点属于现有展开规则，可按声明的公开输入对应；其他人工类型映射不能冒充原算法。

NOT等布尔算法连接至AND/OR时，手册允许省略OUT点声明（REF1100 §4.66 p253）。这不影响已有明确引用指向固定OUT接口；核对不要求MCR对象另写一个OUT点属性。未知输出端口仍不接受。

## 证据范围

“吻合”表示端口建议、当前图与导入审计的明确引用一致。它不证明针脚没有被移动、图形编码已解码、源文件真实性或控制器运行准确性，因此仍需人工选择和依据。报告读取工程中保留的导入快照，不会在后台重新读取或修改磁盘资料。

真实ALR和CPL共53条候选满足比较条件；软件回归验证了逐项比较及模拟人工采用后边数/端口结构不变，原审计仍记录0条直接解码的SVG连接。默认真实导入的72条候选仍待人工处理，其他19条没有同等交叉证据。此测试不是人工作出的现场验收结论。

旧工程若没有完整原审计，会显示证据不足；可继续逐条核线，或先保存人工修改，再重新导入源文件取得新快照。

打开`examples/mcr-connection-review.json`可练习两条连接的报告导出、选择、采用、撤销和重开。该软件夹具保留其他待补信息，用于演示核线工作流。
