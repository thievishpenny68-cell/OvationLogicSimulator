# 输入工况与人工重设

0.46.0界面增加结构化分段表格、示例、即时规律/扫描点预览与跨源草稿，见input-wave-editor.md；下文时间/类型/采样规则保持。

产品0.8.3、核心0.7.2。INPUT是本软件的信号发生工具，不是Ovation算法。时间统一为仿真秒；波形不按浏览器墙钟推进。

## 已支持配置

|mode|字段|含义与边界|
|---|---|---|
|constant|mode、value|固定信号值|
|step|mode、at、before、after|at为非负秒数；t<at取before，t≥at取after|
|ramp|mode、start、value、slope|仅模拟量；start为非负秒数，value为起始值，slope为每秒变化量；开始前保持value|
|table|mode、points|points为严格递增的[秒,值]；节点处切换，之间保持前值|
|linear|mode、points|仅模拟量；相邻节点间线性插值，节点本身取该值|

分段配置至少一个节点，时间非负且不重复。**首节点之前也使用首节点的值，末节点之后保持末值**；若希望初始FALSE、0.5秒后TRUE，需显式填写`[[0,false],[0.5,true]]`。单独填写`[[0.5,true]]`会在仿真起点就得到TRUE。

数字输入只接受布尔true/false，界面使用开关选项。模拟值和斜率必须属于当前正常有限Float32/零范围；信号计算结果也须在此范围。斜坡按`value + max(0,t-start) * slope`生成，分段线性按所配置原值插值，再转换输出为Float32；这是软件输入发生器合同，不证明控制器的内部中间精度。

取样时刻由整数tick与整数微秒周期决定。时间比较不自动添加epsilon、不将毫秒字段换算成秒，也不根据字段名猜测新的信号模式。t=0是输入初始取样；首个执行扫描为一个周期。

## 未支持或损坏的数据

每种模式只接受上表字段。`timeUnit`、`repeat`、频率、其他模式的参数或未知键均明确报错；即使某项值为false或0，也不忽略。模式未知、对象/分段结构损坏、值类型错误、缺字段、负时间和重复时间都阻止运行。原始配置保留在项目中。

载入已有无效配置时，属性区显示错误及原始JSON，并提供“重新配置输入规律”。普通“应用参数”不会把未知数据重写掉。点击重新配置后，原配置记录到该节点的`provenance.waveReplacements`，当前规律回到待选择状态；再由用户明确选择模式和填写数值。此操作可撤销，记录随项目保存。改变信号类型也会保留原波形，再要求配置适合新类型的工况。

对合法波形的编辑，在应用前先校验。输入非法时间或分段数据时提示错误，原工程及原运行记录不被该次失败编辑替换。成功改变工况仍按既有规则清除旧运行，避免混用不同配置的轨迹。

这些记录表示用户重新定义的仿真输入，不代表已解码现场波形、已核实来源或已经取得Ovation运行对照。
