# PACK16稀疏针脚布局建议

0.40.0为PACK16提供待人工核对的槽位建议，标识`cb-packed-pin-layout-v1`。运行内核保持0.28.0，所有算法模型不变。

REF_1100 §4.71 p261完整符号从上到下列出D0～D15，右侧PBPT居中。当前CB原图的完整槽位布局符合高度17等分、两端各留一格的模板；**17等分是本模板匹配条件，不是手册规定的所有符号尺寸。** 左脚在第k+1个位置时建议Dk，右脚建议POUT（PBPT别名）。它依据完整槽位假设，不按所见针脚数量重新编号。

例如原样本高340、槽距20：从上沿偏移260、280、320的三脚对应D12、D13、D15；偏移60、80、100对应D2、D3、D4。省略的脚保持空位，不能把任一组改标为D0、D1、D2。模板使用相对高度，文件名、对象ID、绝对坐标及点名均不硬编码。

## 适用与拒绝

- 仅PACK16矩形、左0～16条水平针脚、右一条居中水平输出，针脚贴合边界。正向平移、轴向缩放可保留。
- 每个输入必须落在完整网格的一处有效槽位，槽位不得重复。若有明确`cb-alg-dN`或`cb-macro-dN`声明，其位集合须与所见槽位完全一致。
- 压缩排列但保留其他位号声明、错位、重复ID、额外输出、混合方向、旋转/反向/斜切、非矩形或明确针脚名冲突均不建议。没有声明而被人工移到另一个合法槽的针脚，仍无法凭几何保证语义；请核对原图。
- UNPACK16手册图使用省略号，没有给出完整16槽位置，本版不套用这个模板。
- 同名自定义宏也不借用标准模板；PACK16及已有标准算法的布局建议均排除ControlMacroReference。

建议仅预选候选卡片的端口草稿，不改写原始针脚名，不生成或确认逻辑边，不补参数、数字输入类型、LP共享身份或初始字。人工填写依据并采用后，仍按原端口类型/驱动冲突规则检查；采用可以撤销/重做并保存。LP整字许可不代表数字引脚可以直接接整字。

## 当前来源核对

真实DSI样本新增8条完整端口建议，与MCR原有明确边逐条对应；四份SVG完整建议总计57→65。原64逻辑对象、72图形连接、82TFT及SHA保持，72候选仍为待人工核对，直接明确解码连接仍为0。节点、语义边、源文件、原始审计与问题清单不变，差异报告见开发审查记录。

这增加了有依据的人工修复草稿，不证明不透明引用已解码、原针脚未移动或实际控制器运行准确性。MCR交叉核对继续要求其原有类型、来源与唯一驱动等条件；位槽建议不会绕过这些检查。
