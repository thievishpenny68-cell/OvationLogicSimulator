# 单路模块的端口布局建议

0.39.0补齐GAINBIAS、ASSIGN、SMOOTH的单输入/单输出布局建议，标识为`cb-unary-pin-layout-v1`。对恰好两个贴合符号边界的针脚，支持上进下出、左进右出；建议输入IN1、输出OUT。运行内核仍为0.28.0，全部算法计算模型不变。

|算法|接口依据|补充说明|
|---|---|---|
|GAINBIAS|REF_1100 §4.42 p174～177，IN1/OUT|只对所见两个针脚的符号给建议；TRIN/TOUT等额外针脚不凭位置省略或赋名|
|ASSIGN|§4.13 p44，IN1/OUT|建议不推断LA/LD/LP；输入输出仍须明确同类型|
|SMOOTH|§4.104 p363，IN1/OUT|SMTH为固定参数，不增加接线端；参数和初态仍须明确|

新建议仅补入候选卡片的预选草稿，不改变原始针脚名，不写入逻辑边，也不填补类型、参数、初态或质量信息。请对照源图，填写人工核对依据后采用；端口不合法、类型未明或不符、目标已有其他驱动时，仍按原规则拒绝。采用可以一次撤销/重做，决定、建议和原来源随工程保存。

重复ID、额外针脚、混合上下/左右布局、重叠或不贴边、旋转/反向/斜切、明确名称冲突及其他算法均不生成本模板建议。明确TRIN/TOUT（含cb-alg-前缀）不改作IN1/OUT；椭圆只接受中轴尖端，包围盒角点不算贴边。正向平移和轴向缩放可保留。原来AND/OR、ONDELAY等模板仍使用原标识，未更改编号规则。

真实DSI资料中的GAINBIAS、ASSIGN新增4条完整双端建议，总计由53增至57条。原4份SVG仍有72条图形连接候选待人工核对，明确解码连接仍为0；原MCR逻辑边、源文件SHA和其他诊断保持。结构差异报告见开发审查记录。

布局可被编辑，所以两个贴边针脚本身不能证明实际方向或名称。原图仍是人工核对对象；不将本模板当作不透明字段解码、MCR语义确认或Ovation运行对照。操作入口沿用`pin-layout-suggestions.md`。
