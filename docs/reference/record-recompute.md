# 运行记录的离线复算 v1

0.66.0/引擎0.30.0：强制输出仅保留当前页面，不写普通工程。带强制的完整运行记录使用版本4证据副本，明确声明强制模型、逐引脚请求／实际值，快照另存未强制计算值；完整复算核对这些内容。主动载入复算结果仅在本页恢复强制，普通项目保存仍不携带。详见[临时强制输出](output-forces.md)。

产品0.8.0，计算核心仍0.7.0。入口“复算记录”读取本软件JSON运行记录，不从输出反推未知工程或现场输入。

## 核对范围

必须包含manifest.project、明确engineVersion/profile/scanModel/numericMode/order/execution，以及连续0..N完整快照（最多10000扫描/10001快照）。工程先经既有结构、来源审计、人工字段和示波器检查，再经核心支持范围检查；不自动补参数、初态或扫描确认。

检查当前引擎支持的相同声明模型；仅对实际使用的定时/监视块要求相应timerModels/monitorModels一致。未知模型、缺失关键声明或工程/声明顺序冲突明确拒绝。工程指纹和结果范围若已附则必须匹配；旧记录缺这两项时明确显示not-present，完整连续快照仍可按已声明工况复算，不伪称核对了缺失项。

逐拍比较全部输出、全部内部状态、时间/扫描号及所有字段，不受当前六路默认显示、信号选择或参考容差影响。使用JSON数值精确相等及严格类型/键集合；额外状态、缺字段、FALSE与0均不能混过。遵守JSON记录语义，-0与0不能据此声明位模式不同。差异计总数，明细最多列200条并保留路径。

记录最后失败尝试时，在最后有效扫描后再执行一次，比较故障code/tick/nodeId/timeUs；不比较可能因版本/文字变化而不同的诊断措辞。故障不得被当作有效快照。复算过程中出现意外失败或任何差异时，不允许载入。

## 临时复算与载入

打开记录暂停当前运行，工程、历史和游标保留。点击“开始复算”后分片执行并显示进度，可关闭或按Escape取消。原生模态框隔离背景编辑/快捷键；取消或差异不会替换现有工程。

全部匹配后可“导出报告”，或明确“载入结果”。载入使用复算的当前引擎状态与已逐帧核对的记录快照，可回看、继续运行及导出。保留记录原工程schema/创建版本，不将格式升级伪装成相同指纹。载入是一次工程替换，可撤销回原工程；既有撤销协议不恢复被替换的旧运行，需保留旧轨迹时先导出。

为降低长记录开销，复算不重复保留第二份完整计算历史；每帧对照后保留已有记录快照，核心只持有当前计算状态。文件在本地读取，无服务端或开发运行时。

## 证据边界

记录引擎与当前版本不同时明确显示双方版本，并在报告中标记engineChanged。此功能以当前引擎按相同声明模型检查记录范围内的一致性，不启动旧引擎，也不证明该旧版本在所有工况下等价。

报告标明ovationRuntimeEvidence=false。指纹和数值一致均不是来源真实性、现场采集或Ovation准确性证明；需要现场对照时仍使用原“轨迹对照”流程，明确来源与容差。缺少manifest.project的现场轨迹不能据本功能猜造工程。

产品0.9.0 / 核心0.8.0：使用GAINBIAS、计时或监视块时，必须具备当前numericValidationModel及相应arithmeticModels/timerModels/monitorModels声明。旧v1或缺失声明明确拒绝，不补猜。无这些块的旧布尔记录继续按其相同规则核对。失败记录载入后在问题页恢复运行诊断，不把失败扫描当快照。

0.19.0/核心0.12.0为实际使用的AAFLIPFLOP/PULSECNT新增stateModels（分别ref1100-2006-aaflipflop-v1、ref1100-2006-pulsecnt-v1）。完整复算要求当前对应声明并核对firstPass/沿记忆等所有快照字段；缺失或未知模型拒绝。参考对照也核对双方已声明stateModels，冲突不能因数值相同而通过；不含新块的旧记录不增加此项要求。见edge-memory.md。
