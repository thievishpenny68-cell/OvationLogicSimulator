## 单次记录上限

界面底部显示当前工程的“记录上限 N 拍”。上限取以下约束的最小值：

- 最多10,000次扫描，另保留t=0快照。
- 全部快照合计最多2,100,000个标量单元。每拍计入tick/time、全部输出、全部内部状态、共享字，以及存在共享点时各打包输入的实际读取值；是否选中观察通道不改变计数。
- 整数微秒时间保持JavaScript安全整数。

这是一项记录资源政策，不是内存字节或运行耗时保证。例如200个单输出节点仍可记录10,000拍；100个输入源加100个25槽TRANSPORT，每帧2,902个单元，可记录722拍及t=0，共723份完整快照。复杂状态图会比简单布尔图更早达到上限。

达到上限时运行立即停止，“运行/单步”按钮停用。已有全部数据保留，可以回看、导出CSV/JSON或复算；导出后点击“复位”开始一轮新实验。复位后的实验从工程规定的初态开始，不承接上一轮末态。回看较早一拍不会腾出记录容量。

载入旧的、更长的完整记录时不截断数据；仍可回看和导出，达到当前上限后不能继续追加。选择“全程上限”的示波器横轴固定为0至当前工程的可记录时长，普通1/5/10/30秒窗口继续先填满、后FIFO滚动。

## 验证范围

引擎保持0.23.0，各算法数值、初态和扫描模型未改变。新增验证覆盖实际字段计数、窗口边界、控件缓存失效、到限后的完整导出与复算。本机Edge完整界面基准使用4倍CPU节流，分别验证布尔图和大量TRANSPORT状态图，逐份快照与独立内核复跑比较；结果见开发审查记录。

CPU节流不能代替另一台日常电脑试用；CDP的JS堆为瞬时采样，不是操作系统内存峰值。单次记录上限也不限制导入资料大小或模块数量，因此载入大型SVG、全历史绘图及导出仍可能需要等待。
