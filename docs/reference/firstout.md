# FIRSTOUT首出报警（0.27.0）

依据REF_1100（2006-05）§4.39 p163～167。当前46种可执行手册算法，核心0.18.0；本块不使用模拟近似运算，布尔、位图和计数均精确。

|引脚|类型/基础记录|规则|
|---|---|---|
|RST|数字LD/LP，必接|FALSE禁用；FALSE→TRUE重新待命|
|IN1～IN16|数字LD/LP，逐路可选|只监视相连接输入的新上升沿，不用补齐未接输入|
|MNTR|LP整字|IN1对应第0位，IN16对应第15位|
|MULT|数字LD/LP|首出周期同时上升的输入数量>1|
|NTRP|模拟LA|首出周期上升的输入数量，0～16整数|
|TRPD|数字LD/LP|跳闸指示|

手册p164文字提及STATE，但p163图和p167正式输出表只有这四个输出；软件不新增STATE或OUT端口。内部`mode`表示0禁用、1待命、2跳闸，可从属性、记录或探针观察。

## 扫描行为

RST从FALSE变TRUE时，四个输出清零并采集当拍输入位图作基线，已有TRUE不会触发。待命后，首次出现一个或多个新上升沿便锁存首出结果：

- MCFG=0（默认）：MNTR记录所有同期新沿。
- MCFG=1：MNTR只保留最低编号新沿；MULT、NTRP仍反映真实同期数量，不能把NTRP改成1。
- 跳闸后且RST保持TRUE时，输入恢复或晚到的新沿都不能替换第一次事件。
- 必须先RST=FALSE，再RST=TRUE，才能重新待命。新的RST上升再次忽略当时已置位输入。

p165时序图明确RST下降时TRPD清零；正文只说明禁用时不执行，没有明确给出MNTR/MULT/NTRP的禁用值。本软件按“不执行”保留这三项报告，直至重新待命才清零。**后三项禁用保持属于明确的软件约定，尚无Ovation运行对照，不能当成所有控制器版本已证实行为。** 两种MCFG及新沿锁存规则则直接来自正文和表格。

## 明确软件起点

新建实例提供可编辑的清空初态。导入不会补初态；须在属性区明确四输出和以下三项：

- `mode`：0禁用、1待命、2跳闸。
- `previousRST`：起点前RST，禁用须FALSE，其余模式须TRUE。
- `previousMask`：起点前输入位图，0～65535，可输入0x十六进制。

TRPD须与跳闸模式一致；NTRP须为0～16整数，MULT与NTRP>1一致。待命报告必须清零，跳闸MNTR位数须符合MCFG及NTRP。矛盾、缺失或错误类型明确拒绝，不猜硬件重启状态。软件复位返回这些配置初态。

MNTR可直接连接UNPACK16，或在属性中绑定明确共享LP字。待命/新跳闸按规则写位图；禁用及已锁存阶段不重复写共享字。共享名称/初值、别名、执行顺序和整拍失败回滚遵守packed-words.md。若其他明确写者修改同一字，观察到的是该点当前记录值，内部首出状态与计数仍保持自己的首次事件。

## 示例和证据

打开`examples/firstout.json`，周期100ms，单步9次。两个FIRSTOUT分别为MCFG0/1。0.1秒重新待命忽略已有IN1；0.3秒IN1/IN16同时新沿：MNTR分别0x8001/0x0001，两块MULT均TRUE、NTRP均2、TRPD均TRUE。0.4秒禁用只清TRPD；0.5秒重新待命清报告；0.7秒再次首出。

静态`examples/firstout-reference.json`以手册文字、时序图及上述明示软件约定独立编写，未调用模拟引擎。仅选择all和low的四输出及all.mode，零容差对照应有90/90项一致（80输出、10内部模式）。全65536位图×2模式、稀疏输入、锁存/重待命、同扫描级联、共享位图、显式初态、缺态/错误类型、故障原子性、保存重跑和完整模型复算均有回归。

手册外形采用p163长矩形、17路左侧输入、4路右侧输出、内部FIRSTOUT标记和实心箭头；交互端点继续以方形/圆形/六边形区分数字、模拟和LP字。质量范围保持GOOD，不模拟硬件报警质量或未解析LP位地址。
