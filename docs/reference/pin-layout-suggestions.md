# 针脚布局建议

0.10.0新增，建议依据标识`cb-symbol-pin-layout-v1`。对未识别针脚名的连接候选，使用已知符号的针脚数量和位置生成端口建议，显示在“检查与导入问题”的候选卡片上。可用建议会预选到下拉框，仍是待核对草稿。

0.39.0另支持GAINBIAS、ASSIGN、SMOOTH的上下/左右单路布局；原模板不变。具体条件与真实来源差异见`unary-pin-layout.md`。

0.40.0增加PACK16完整16槽建议，稀疏输入保留实际位号，详见`packed-pin-layout.md`；当前完整建议65/72，全部候选仍须人工核对采用。

## 如何采用

1. 对照原图核对源块、目标块、针脚和连线。建议显示所见输入/输出针脚数量及端口名。
2. 补齐数字/模拟接口类型和必要参数。AND/OR缺失输入数量时，建议中的图形数量可供参考，参数栏仍需人工填写。
3. 修改任何不符的选择，填写核对依据，再点击“采用连接”。空依据、非法端口、类型不符或目标已有其他驱动仍拒绝。
4. 补齐其余字段、初态和扫描计划后运行。采用可撤销/重做，建议、原始信息和人工决定随工程保存重开。

预选不会写入连接，也不会确认参数、输入类型、初态或原始字段。未采用候选继续阻止运行；已有MCR语义边不等于SVG候选已经确认。旧项目没有建议时继续按原方式人工配置。

## 本版生成建议的布局

|符号|所见针脚布局|建议|
|---|---|---|
|INPUT / OUTPUT|只有一个可见针脚，可为竖向|OUT / IN1|
|NOT、OFFDELAY、ONESHOT、HIGHMON、LOWMON|左一右一|IN1 / OUT|
|ONDELAY|左二右一|左侧从上到下IN1、ENBL；右OUT|
|AND / OR|左2～8、右一|左侧从上到下IN1～INn；右OUT|

算法符号须有可识别矩形/椭圆边界，水平针脚贴合左右边界，坐标与对象身份明确；正向平移/缩放可保留建议。旋转、反向或斜切、重叠、额外输出、不支持数量、已明确名称与建议冲突等情况下不提供该算法建议。宏接口及未支持算法不凭位置赋名。

## 依据与限制

用户提供的ALR/CPL在CB Editor中的截图用于核对针脚标签与位置。用ALR建立模板，再与CPL及两份MCR交叉核对：ALR 20条、CPL 33条完整建议均找到相同端口的MCR语义边；节点关联使用记录名、输出符号或引用集合，未使用“唯一类型”布局替代。

[原厂OW360_80 §10.2.3，p171](https://www.scribd.com/document/1074913833/OW360-80)允许移动针脚。因此位置并非语义保证，自定义/移动过的符号仍须逐针脚审查；这些建议不能证明`cb-key`或编码引用已被解码，也不是Ovation运行采集证据。四真实SVG仍是72条待确认候选、0条直接解析的明确连接；0.40补齐PACK16模板后其中65条具备双端完整建议。

0.12.0补充：AND/OR明确cb-alg-inN集合与连续编号假设不一致时，不给出该块的布局编号建议。原始引脚和候选保留供人工核对，避免将非连续IN8建议为IN3。

0.13.0可将完整建议与当前已有MCR边及原导入审计交叉核对，人工选择/填写依据后成组采用。建议本身仍不自动确认；MCR交叉报告及限制见mcr-connection-review.md。
